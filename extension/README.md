# 代购选品助手（Chrome 插件）

`daigou-cart-import` 命令行工具的浏览器版本：把客户表格里的商品链接批量导入成一个待办清单，
用后台标签页一批批打开，替代"一个个手动找链接"这一步。

## 这个插件做什么、不做什么

- **做**：解析表格 → 生成清单 → 在后台标签页帮你打开商品页面。
- **不做**：不会自动点击任何网站上的"加入购物车"按钮，不模拟登录、不操作你账号的任何东西。
  打开的标签页之后要不要买、加不加购物车，都是你自己在网页上手动操作。

这是故意这样设计的：自动点击第三方网站的购物车按钮，即使做得再慢，本质上也是在绕过对方网站的
反自动化检测，多数电商网站的用户协议都禁止这类自动化操作，一旦被发现通常是**封号**。这个插件
只做"帮你把链接批量开出来"这一步——这和你自己手动挨个复制链接打开是同一件事，只是快很多，
不涉及自动化操作目标网站，没有账号风险。

## 单人版，不是团队共享

数据存在你自己浏览器的本地存储（`chrome.storage.local`），只有你自己能看到、管理你自己导入的清单。
每个人在自己电脑上装一份，用自己的账号手动完成加购物车、下单——这跟"每个人有自己的账号"是匹配的，
不是团队共享同一份数据。

## 安装（开发者模式加载，还没上架 Chrome 应用商店）

1. Chrome 打开 `chrome://extensions`
2. 右上角打开"开发者模式"
3. 点"加载已解压的扩展程序"，选择这个 `extension/` 文件夹
4. 浏览器工具栏会出现插件图标，点开就是弹出面板

## 使用

1. 打开插件面板，粘贴客户的表格分享链接（Google Sheets 需设为"知道链接的任何人可查看"），点"拉取"；
   或者点"选择文件"直接上传一份 CSV 文件（不需要公开分享）。
   **"拉取"目前只保证 Google Sheets 链接能用**——浏览器插件跨域拉取内容要在 `manifest.json` 的
   `host_permissions` 里预先声明允许的域名，现在只声明了 `docs.google.com`。如果客户用的是别的表格
   平台（腾讯文档等）导出的直链，拉取会因为跨域被浏览器拦截；这种情况建议先让客户导出 CSV 文件，
   走"选择文件"上传。要支持某个新平台的链接，在 `manifest.json` 里把它的域名加进 `host_permissions`
   即可。
2. 表格格式和列名要求跟命令行版一样，见仓库根目录的 README（商品链接/数量/规格/备注，中英文表头都支持）。
3. 导入后清单里会列出每一条商品。可以：
   - 点单条的"打开"，在后台标签页打开这一条，自动标记为已处理；
   - 设置"每批打开"的数量，点"打开下一批"分批处理，避免一次开几十个标签页；
   - 点"打开全部剩余"一次性开完所有还没处理的。
4. 已处理的条目会变灰，勾选框可以手动改状态（比如打开后发现商品下架了，想标记但不想删除）。
5. 客户表格改了之后重新拉取/上传一次是安全的：同一条链接会更新数量/备注，不会重复出现，也不会把已经处理过的状态重置成待处理。

## 测试

```bash
cd extension
node test/run-tests.mjs
```

覆盖表格解析（和命令行版共用同一套逻辑）、清单的新增/合并/去重、状态切换、删除和清空。
`store.js` 用一个内存版的 `chrome.storage.local` 模拟实现测试，不需要真的打开浏览器。

## 和命令行版（仓库根目录 `src/`）的关系

两者共享同一套表格解析逻辑（`toCsvExportUrl` / `parseCsv` / `normalizeRow`），是直接复制过来的纯 JS 代码，
没有走 npm 包/构建工具，改动的时候要留意两边会不会跑偏。存储部分不共用：命令行版写本地 JSON 文件
（模拟你们代购平台的购物车，等真接后端时替换），插件版写 `chrome.storage.local`（单人的处理清单，
不是购物车数据）——这是两种不同的使用场景，不是同一份数据的两个入口。
