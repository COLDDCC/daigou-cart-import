# 购物车助手（Chrome 插件）

把一份表格里某一列的链接批量在后台标签页打开——替代"一个个手动找链接"这一步。
最早是给代购场景做的（客户发商品表格 → 找链接 → 加购物车），但链接所在的列名可以自定义，
所以任何"表格里一列是链接，想批量打开"的需求都能用，不限于代购。

## 这个插件做什么、不做什么

- **做**：解析表格 → 生成清单 → 在后台标签页帮你打开链接。
- **不做**：不会自动点击任何网站上的按钮（比如"加入购物车"），不模拟登录、不操作你账号的任何东西。
  打开的标签页之后要做什么，都是你自己手动操作。

这是故意这样设计的：自动点击第三方网站上的按钮，即使做得再慢，本质上也是在绕过对方网站的
反自动化检测，多数网站的用户协议都禁止这类自动化操作，一旦被发现通常是**封号**。这个插件
只做"帮你把链接批量开出来"这一步——这和你自己手动挨个复制链接打开是同一件事，只是快很多，
不涉及自动化操作目标网站，没有账号风险。

即便只是批量打开标签页，如果目标网站本身有比较敏感的反机器人机制，短时间内密集打开同一个域名
下的很多链接，也可能被识别成异常流量（弹验证码之类）。遇到这种情况**不要**想着调小间隔/加随机延迟
去绕过检测——正确的做法是把"每批打开"的数量调小、甚至只用逐条打开，用更接近人手动操作的节奏去用它。

## 单人版，不是团队共享

数据存在你自己浏览器的本地存储（`chrome.storage.local`），只有你自己能看到、管理你自己导入的清单。
每个人在自己电脑上装一份，用自己的账号——这跟"每个人有自己的账号"是匹配的，不是团队共享同一份数据。

## 安装（开发者模式加载，还没上架 Chrome 应用商店）

1. Chrome 打开 `chrome://extensions`
2. 右上角打开"开发者模式"
3. 点"加载已解压的扩展程序"，选择这个 `extension/` 文件夹（不是仓库根目录，是 `extension` 这一层）
4. 浏览器工具栏会出现购物车图标的插件

## 界面：常驻小窗口，不是下拉 popup

点工具栏图标打开的是一个**独立的小窗口**，不是点别处就自动消失的下拉面板——这样你打开一批标签页、
切换过去看一眼，插件窗口还在，不用重新点图标打开。不用的时候点窗口右上角的 **×** 关掉就行，
或者用窗口自带的关闭按钮也一样。再次点工具栏图标，如果窗口还开着会直接把它切到前台，不会重复开出好几个。

## 使用

1. 打开插件，粘贴表格分享链接（Google Sheets 需设为"知道链接的任何人可查看"），点"拉取"；
   或者点"选择文件"直接上传一份 CSV 文件（不需要公开分享）。
   **"拉取"目前只保证 Google Sheets 链接能用**——浏览器插件跨域拉取内容要在 `manifest.json` 的
   `host_permissions` 里预先声明允许的域名，现在只声明了 `docs.google.com`。如果用的是别的表格
   平台（腾讯文档等）导出的直链，拉取会因为跨域被浏览器拦截；这种情况建议先导出 CSV 文件，
   走"选择文件"上传。要支持某个新平台的链接，在 `manifest.json` 里把它的域名加进 `host_permissions` 即可。
2. **链接所在列的表头名**可以填，也可以留空：
   - 留空：自动识别"商品链接/链接/url/link"等几个常见列名（大小写不敏感）。
   - 填了：直接按你填的这个列名去找链接，不管这一列叫什么都行——这是让插件能用在任何表格上的关键。
   - 数量/规格/备注这三列目前还是走固定的常见列名识别（数量/qty、规格/sku、备注/note 等），
     都是选填，没有也不影响链接被打开。
3. 导入后清单里会列出每一条。可以：
   - 点单条的"打开"，在后台标签页打开这一条，自动标记为已处理；
   - 设置"一次打开"的数量，点旁边的"打开"按钮分批处理；
   - 点"打开全部剩余"一次性开完所有还没处理的——目标网站没有反机器人机制、链接数量不多时再用这个，
     否则建议用上面两种更保守的方式。
4. 已处理的条目会变灰，勾选框可以手动改状态（比如打开后发现链接失效了，想标记但不想删除）。
5. 表格改了之后重新拉取/上传一次是安全的：同一条链接会更新数量/备注，不会重复出现，也不会把已经处理过的状态重置成待处理。

## 测试

```bash
cd extension
node test/run-tests.mjs
```

覆盖表格解析、清单的新增/合并/去重、状态切换、删除和清空。`store.js` 用一个内存版的
`chrome.storage.local` 模拟实现测试，不需要真的打开浏览器；这个仓库也用真实 Chromium（Playwright）
手动验证过弹窗渲染和"打开"按钮确实会创建后台标签页，但这部分不在自动化测试里，改动界面之后建议
重新装一遍手动点一遍。

## 和命令行版（仓库根目录 `src/`）的关系

两边共享 `toCsvExportUrl` / `parseCsv` 这两个模块，是直接复制过来的纯 JS 代码，没有走 npm 包/构建工具。
`normalize.js` 这一份已经和命令行版的 `src/normalize.mjs` **分叉**了：插件版支持传入自定义的链接列名
（`normalizeRow(row, rowNumber, { urlColumn })`），命令行版没有这个参数。以后改这几个文件时留意这一点，
不要想当然地以为两边还是完全一样的代码。

存储部分完全不共用：命令行版写本地 JSON 文件（模拟代购平台的购物车，等真接后端时替换），插件版写
`chrome.storage.local`（单人的待打开清单，不是购物车数据）——两种不同的使用场景，不是同一份数据的两个入口。
